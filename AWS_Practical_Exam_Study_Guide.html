Q1 IAM — Users, Groups, Policies & MFA
IAM EC2 S3
What is IAM?
Identity and Access Management (IAM) is AWS's free service that controls who can do what on your AWS account. It is global (not region-specific). IAM follows the Principle of Least Privilege — give users only the permissions they absolutely need.
Core IAM Components
👤 Users
Individual people/apps. Have permanent credentials (password + access keys).
👥 Groups
Collection of users. Attach policies to groups, not individual users. Best practice.
📋 Policies
JSON documents that define Allow/Deny for Actions on Resources. Attached to users/groups/roles.
🎭 Roles
Temporary permissions. Used by EC2 instances, Lambda, cross-account access.
🔐 MFA
Multi-Factor Auth. Second factor beyond password. Virtual (Google Authenticator) or hardware.
Group → Policy Mapping (Exam Table)
GroupPolicyWhat the user CAN doWhat they CANNOT do
S3-SupportAmazonS3ReadOnlyAccessView/list S3 buckets & objectsUpload, delete, modify S3; anything EC2
EC2-SupportAmazonEC2ReadOnlyAccessDescribe/view EC2 instancesStart, stop, terminate instances
EC2-AdminAmazonEC2FullAccessView, start, stop, terminate EC2S3 access (unless separately granted)
MFA Enforcement Policy Logic
The custom MFA-Enforcement-Policy uses BoolIfExists: aws:MultiFactorAuthPresent = false as a condition to Deny everything except MFA-related actions. This means: if a user logs in without MFA, they can only set up their MFA device — nothing else works until they re-login with MFA.
⚠️
Key exam point: MFA enforcement requires BOTH setting up the MFA device AND confirming subscription. Without clicking "Confirm Subscription" in email, SNS alerts don't reach you.
Q2 Amazon EBS — Storage, Backup & Data Recovery
EBS EC2
What is EBS?
Elastic Block Store (EBS) is a persistent, network-attached block storage device for EC2. Think of it as a virtual hard drive. It persists independently of the EC2 instance lifecycle — data survives instance stop/start. EBS volumes are Availability Zone specific — you cannot attach a volume in us-east-1a to an instance in us-east-1b.
Key Concepts
📦 Volume
The actual storage unit. Must be in same AZ as EC2 instance.
📸 Snapshot
Point-in-time backup of a volume stored in S3 (managed by AWS). Used to create new volumes or copy across AZs.
🔄 Restore
Create a new EBS volume FROM a snapshot. The data is immediately available. No need to run mkfs.
🗂️ Mount Point
Linux directory where the volume is attached (e.g., /mnt/my-data). Must mount after attach.
Linux Commands You Must Know
# See all block devices (disks) lsblk # Format new volume with ext4 filesystem (ONLY for NEW volumes) sudo mkfs -t ext4 /dev/xvdf # Create a mount point directory sudo mkdir /mnt/my-data # Mount the volume sudo mount /dev/xvdf /mnt/my-data # Write test data echo "This is my backup test" | sudo tee /mnt/my-data/testfile.txt # Mount RESTORED volume (NO mkfs needed — data already exists!) sudo mkdir /mnt/recovered-data sudo mount /dev/xvdg /mnt/recovered-data # Verify recovery cat /mnt/recovered-data/testfile.txt
🚨
Critical: NEVER run mkfs on a restored volume. It will wipe your recovered data. Only run mkfs on brand-new blank volumes.
Q3 Amazon S3 — Store, Retrieve & Public Access
S3 IAM
What is S3?
Simple Storage Service (S3) is object storage — not a filesystem. You store objects (files) inside buckets. S3 is globally unique for bucket names. There's no folder hierarchy (it simulates folders with key prefixes). S3 is 99.999999999% (11 nines) durable.
🪣 Bucket
Top-level container. Name must be globally unique across ALL of AWS.
📄 Object
A file + metadata. Max 5TB per object. Accessed via URL.
🔒 ACL
Access Control Lists. Legacy method. Prefer bucket policies instead.
📜 Bucket Policy
JSON policy applied to entire bucket. Controls public/private access.
Public Access Policy (memorize this JSON)
{ "Version": "2012-10-17", "Statement": [{ "Sid": "PublicReadGetObject", "Effect": "Allow", "Principal": "*", // * means everyone (public) "Action": "s3:GetObject", // read-only "Resource": "arn:aws:s3:::YOUR-BUCKET-NAME/*" }] }
⚠️
Two-step public access: (1) Uncheck "Block all public access" on bucket, AND (2) Add bucket policy. Both steps are required. Missing either step = files remain private.
Q4 Amazon RDS — Relational Database Setup & Connection
RDS VPC/SG
What is RDS?
Relational Database Service (RDS) is a managed database service. AWS handles patching, backups, hardware provisioning, and replication. You just manage your database and data. Supports MySQL, PostgreSQL, MariaDB, Oracle, SQL Server, and Aurora.

S3 can serve static HTML/CSS/JS files directly as a website. No server needed. The website gets a public URL like: http://bucket-name.s3-website-us-east-1.amazonaws.com. This is a common way to host frontend applications cheaply.

Q6 CloudWatch — Monitoring, Metrics & Alarms
CloudWatch EC2 SNS
What is CloudWatch?
CloudWatch is AWS's monitoring and observability service. It collects metrics, logs, and events from AWS services. Think of it as a dashboard + alerting system. Default metrics are collected every 5 minutes. Detailed monitoring (every 1 minute) costs extra.
Key Metrics for EC2
MetricWhat it measuresNormal range
CPUUtilization% of CPU being used0–100%
DiskReadOpsNumber of read ops from EBSDepends on workload
NetworkInBytes received by instanceDepends on traffic
NetworkOutBytes sent by instanceDepends on traffic
Alarm → SNS Flow
CloudWatch Alarm → State changes to ALARM → triggers SNS Topic → SNS sends email to subscribed address. You must confirm subscription by clicking the link AWS emails you, otherwise no alerts are delivered.
CPU Stress Command
# Run this to spike CPU to ~100% (tests the alarm) sha1sum /dev/zero & # Check it's working top # Press q to exit # Stop the load after alarm triggers killall sha1sum
ℹ️
CloudWatch checks every 5 minutes by default. After running the stress command, wait 5–10 minutes to see the alarm go red and receive the email.

Apache on Amazon Linux

Resize Concepts

Requires STOP → Change type → START. Changes CPU/RAM. Example: t2.micro → t3.micro.

Q8 VPC — Custom Network with Public & Private Subnets
VPC EC2
VPC Architecture
A Virtual Private Cloud (VPC) is your own isolated network within AWS. Every VPC has a CIDR block (e.g., 10.0.0.0/16). You carve subnets out of it. Public subnets have an Internet Gateway route. Private subnets use a NAT Gateway for outbound internet (updates) but are not reachable from outside.
🌐 Internet Gateway
Allows traffic in from the internet. Attached to VPC. Route table must point 0.0.0.0/0 → IGW.
🔀 NAT Gateway
Lets private subnet instances reach internet (for updates). Blocks inbound connections.
📡 Route Table
Rules that define where network traffic goes. Each subnet is associated with one route table.
🔒 Security Group
Virtual firewall at instance level. Stateful — return traffic is automatically allowed.
🚧 NACL
Network ACL — stateless firewall at subnet level. Both inbound AND outbound rules needed.

Q9 CloudTrail — Activity Logging & Audit
CloudTrail S3
What is CloudTrail?
CloudTrail records every API call made in your AWS account — via Console, CLI, or SDK. It answers: Who did what, when, and from where? It's your security audit log. Logs are stored in an S3 bucket as compressed JSON (.gz files).
📋 Trail
Configuration that defines what to log and where to store it.
📅 Event History
Last 90 days of management events. Searchable instantly in console.
🪣 S3 Storage
Permanent log storage. JSON.gz files. Path: AWSLogs/AccountID/CloudTrail/Region/Year/Month/Day/
🌍 Multi-Region
"Apply to all regions: Yes" ensures logs from every region are captured.
✅
To quickly verify CloudTrail is working: stop an EC2 instance, then check Event History for StopInstances event. You'll see exactly who stopped it and when.
Q9b Terraform — Infrastructure as Code (IaC)
Terraform EC2
What is IaC / Terraform?
Infrastructure as Code means defining your cloud infrastructure in configuration files instead of clicking the console. Terraform by HashiCorp is the most popular IaC tool. It is declarative — you describe the end state, Terraform figures out how to get there.
Terraform Workflow
CommandWhat it does
terraform initDownloads provider plugins (AWS plugin). Run once per project.
terraform planPreview what will be created/changed/destroyed. No changes made.
terraform applyActually creates the infrastructure. Type yes to confirm.
terraform destroyDeletes all resources defined in your config. Type yes to confirm.
🚨
Always run terraform destroy after the exam to avoid unexpected AWS charges from resources left running.
Q10 Elastic Beanstalk — PaaS Application Deployment
Beanstalk EC2 IAM
What is Elastic Beanstalk?
Elastic Beanstalk is AWS's Platform as a Service (PaaS). You upload your application code and AWS automatically handles: EC2 provisioning, load balancing, auto scaling, monitoring, and deployment. You retain full control over the underlying resources. It supports Python, Node.js, Java, PHP, Ruby, Go, .NET.
📦 Application
Top-level container. Holds all versions and environments.
🌿 Environment
Running version of your app. Can be Web Server or Worker.
🎭 IAM Roles
Needs service role + EC2 instance profile. Must be created before launching.
IaaS vs PaaS Comparison
AspectIaaS (EC2)PaaS (Beanstalk)
You manageOS, runtime, app, dataOnly app code and data
AWS managesHardware onlyHardware + OS + runtime + platform
ControlFull controlLess control, more convenience

Q1 IAM: Users, Groups, Policies, MFA — Full Walkthrough
IAM
Step 1: Create Groups & Attach Policies
  1. Go to AWS Console → IAM → User groups → Create group
  2. Name it S3-Support, scroll down, search for and attach AmazonS3ReadOnlyAccess. Create.
  3. Repeat: Create EC2-Support → attach AmazonEC2ReadOnlyAccess
  4. Repeat: Create EC2-Admin → attach AmazonEC2FullAccess
Step 2: Create IAM Users
  1. Go to IAM → Users → Create user
  2. Name: user-1. Check "Provide user access to AWS Management Console". Set custom password. Uncheck "must reset password". Click Next.
  3. On "Set permissions" page — click Next without adding to group (we do it in step 4)
  4. Repeat for user-2 and user-3
Step 3: Create MFA Enforcement Policy
  1. Go to IAM → Policies → Create policy
  2. Click JSON tab, paste the MFA enforcement JSON (AllowUserToManageTheirOwnMFA + DenyEverythingIfNoMFA statements)
  3. Name it MFA-Enforcement-Policy. Click Create policy.
Step 4: Assign Users to Groups
  1. Go to IAM → User groups → S3-Support → Users tab → Add users → select user-1
  2. Go to EC2-Support → Add user-2
  3. Go to EC2-Admin → Add user-3
  4. Attach MFA-Enforcement-Policy to ALL three groups (Permissions tab → Add permissions → Attach policies)
Step 5: Verify
  • Log in as user-1 → should see S3 buckets but get "access denied" on EC2
  • Log in as user-3 → should be able to start/stop EC2 instances
  • Log in as any user WITHOUT MFA → all actions denied except MFA setup
Q2 EBS: Full Storage + Backup + Recovery Cycle
EBSEC2
Steps 1–3: Create, Attach & Mount
  1. EC2 → Elastic Block Store → Volumes → Create volume. Size: 1 GiB, AZ: must match your EC2 instance (e.g., us-east-1a). Click Create.
  2. Select new volume → Actions → Attach volume. Choose your EC2 instance. Note device name (/dev/sdf). Click Attach.
  3. Connect to instance via EC2 Instance Connect. Run: lsblk to confirm disk appears (shows as xvdf)
  4. Format it: sudo mkfs -t ext4 /dev/xvdf
  5. Create mount point: sudo mkdir /mnt/my-data
  6. Mount: sudo mount /dev/xvdf /mnt/my-data
Step 4: Write Data
  1. Write file: echo "This is my backup test" | sudo tee /mnt/my-data/testfile.txt
  2. Verify: ls /mnt/my-data → should show testfile.txt
Steps 5–8: Snapshot, Restore & Verify
  1. EC2 → Volumes → Select your 1GiB volume → Actions → Create snapshot. Description: "Lab Backup". Wait for status: Completed.
  2. EC2 → Snapshots → Select snapshot → Actions → Create volume from snapshot. Same AZ. Click Create.
  3. Go back to Volumes → select the NEW restored volume → Actions → Attach volume → same EC2 instance. New device name will be /dev/sdg → appears as xvdg.
  4. In terminal: sudo mkdir /mnt/recovered-data
  5. Mount: sudo mount /dev/xvdg /mnt/recovered-data (NO mkfs!)
  6. Verify: cat /mnt/recovered-data/testfile.txt → should show "This is my backup test" ✅

Q7 EC2 Web Server: Install Apache + Resize Instance & Storage
EC2
Part A: Install Web Server
  1. Connect to your Amazon Linux EC2 via EC2 Instance Connect.
  2. Run: sudo yum update -y then sudo yum install -y httpd
  3. Run: sudo systemctl start httpd and sudo systemctl enable httpd
  4. Create page: echo "<h1>Welcome to My EC2 Web Server</h1>" | sudo tee /var/www/html/index.html
  5. Security Group → Inbound Rules → Add HTTP (port 80), Anywhere (0.0.0.0/0).
  6. Copy instance Public IPv4 → paste in browser → see your page. ✅
Part B: Change Instance Type
  1. EC2 → select instance → Instance state → Stop. Wait until Stopped.
  2. Actions → Instance Settings → Change instance type. Select t3.micro. Apply.
  3. Start the instance again.
Part C: Modify EBS Volume
  1. EC2 → Volumes → select root volume (attached to your instance).
  2. Actions → Modify volume. Change size from 8 GiB to 10 GiB. Modify → Confirm.
